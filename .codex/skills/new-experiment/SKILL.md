# Новый эксперимент

Используй этот скилл, когда пользователь просит начать новый ML-эксперимент в текущем Git-репозитории.

## Работа с учетными данными

Для обращения к GitHub найди `.env` в корне репозитория и прочитай из него только `GH_TOKEN` или `GITHUB_TOKEN` и, при наличии, `GITHUB_USERNAME`. Не исполняй `.env` как shell-скрипт, не выводи секрет и не помещай токен в URL. Перед `fetch` передай токен через `GH_TOKEN` только в окружение текущего процесса, проверь `gh auth status` и выполни `gh auth setup-git`. Если `.env`, токен, `gh` или аутентификация недоступны, остановись и сообщи причину без раскрытия секрета.

## Обязательный результат

Для имени эксперимента `<experiment-name>`:

- создать Git-ветку с точным именем `<experiment-name>`;
- создать в корне репозитория папку `<experiment-name>`;
- внутри нее создать каталоги `data`, `models`, `notebooks`, `realization` и `results`;
- добавить в каждый пустой каталог файл `.gitkeep`, чтобы структура отслеживалась Git.

Итоговая структура:

```text
<experiment-name>/
├── data/
│   └── .gitkeep
├── models/
│   └── .gitkeep
├── notebooks/
│   └── .gitkeep
├── realization/
│   └── .gitkeep
└── results/
    └── .gitkeep
```

## Порядок действий

1. Найди корень текущего репозитория командой `git rev-parse --show-toplevel`. Если текущая папка не находится внутри Git-репозитория, остановись и сообщи об этом пользователю.
2. Получи имя эксперимента из запроса пользователя. Если оно не указано, задай один короткий уточняющий вопрос.
3. Убедись, что имя одновременно является допустимым именем ветки и одним безопасным именем каталога: оно не должно содержать `/` или `\`, быть `.` или `..` либо зарезервированным системным именем. Проверь ветку командой `git check-ref-format --branch <experiment-name>`. Не исправляй и не нормализуй имя молча: при ошибке попроси другое имя.
4. Аутентифицируйся по правилам выше и выполни `git fetch origin`. Проверь, что ветки с таким именем нет ни локально, ни в `origin`, а папка `<experiment-name>` еще не существует. Ничего не перезаписывай. При конфликте остановись и перечисли найденные совпадения.
5. Проверь `git status --short`. Не удаляй, не прячь через stash и не коммить чужие незавершенные изменения. Если рабочее дерево не чистое, остановись и попроси пользователя сначала разобраться с изменениями.
6. Создай новую ветку от полученного актуального удаленного `main`: `git switch -c <experiment-name> origin/main`.
7. Создай указанную структуру каталогов и файлы `.gitkeep`.
8. Проверь результат командами `git branch --show-current`, `git status --short` и просмотром созданного дерева.

Не создавай коммит и не отправляй ветку на GitHub, если пользователь отдельно об этом не попросил. В финальном сообщении укажи имя ветки, путь к папке эксперимента и созданные каталоги.
